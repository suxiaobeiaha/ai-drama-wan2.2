# 决策记录(D1-D11)

> 每个决策:选了什么、为什么、备选是什么。原始文件:E:\ai\story2video\优化线路与决策树.md

## D1 视频模型:Wan 2.2 TI2V-5B ✅
- 16GB AMD 卡能跑;MiniMax H3(33B)不现实;A14B 需 24GB+
- 关键知识:5B 是 48 通道@/16 压缩潜空间,必须 Wan22ImageToVideoLatent 节点 + wan2.2_vae

## D2 推理后端:原生 ROCm ✅
- DirectML 不支持 FP8/GGUF;venv 在嵌入式 Python 上段错误 → torch 直装 python_embeded

## D3 模型下载源:ModelScope ✅
- 每文件 8 连接 ≈ 4.5MB/s;hf-mirror 仅 0.7MB/s(xet US 桥)
- 注意:ModelScope 元数据文件大小可能报错(比实际大 546KB 的坑,交叉验证 hf-mirror 才破案)

## D4 编剧模型:14B+27B 组合拳 ✅
- Lumen 14B 快写(方向/梗概/草稿);qwen3.6 27B 精修(重写而非续写)
- 27B 是思考型,长输出不稳定;重写(锁结构)比续写快且稳
- JSON 只用扁平字符串 schema(8B/14B 对嵌套对象会吐空 {})

## D5 LLM 与视频生成 GPU 排他 ✅
- 两 HIP 进程同占 GPU 会死锁;ComfyUI 空闲驻留 3.5GB 就够卡死 LLM 加载

## D6 视频规格演进 ✅
- 480p×33(冒烟)→ 480p×49(首版)→ 720p×61(测试)→ 1280×544×121(正式,宽银幕 2.35:1)
- 帧数必须 4n+1(33/49/61/81/121),60 不合法;121 帧=5 秒是模型上限

## D7 每镜重启 ComfyUI ✅(最重要规避)
- ROCm 二镜诅咒:同进程第二个生成产出单帧坏结果,30 秒假成功
- 规避:每镜重启服务器(每镜 +40 秒 + 模型重载 30 秒)

## D8 角色一致性:首镜定角色 + I2V ✅
- 资产审查通过后,主角图复制为 assets/char_ref.png,后续全镜 I2V

## D9 旁白:SAPI → edge-tts ✅
- edge-tts(晓晓)+ 情绪标签映射语速音调;无标签自动 LLM 推断+杂质清理

## D10 断点续跑与产物管理 ✅
- 各阶段逐项落盘;改配置后必须清旧 clip/audio 缓存,否则拼接复用旧片段

## D11 画质路线:Seedance 对比结论 ⏳ 推进中
- 结论:本地 16GB 卡达不到商业视频模型级别(模型代差,工程救不了)
- 三路径:本地升级 HunyuanVideo-1.5 / 混合即梦 API(适配层已完成)/ 云 GPU(不推荐)
- 即梦实测数据:fast 版约 109,431 token/条 5 秒 720p;军旅题材审核 9 连拒;审核拦截不扣费
- 决策状态:制片人要求"烧钱要烧出成片",题材转向非敏感类型,实验框架就绪待素材
